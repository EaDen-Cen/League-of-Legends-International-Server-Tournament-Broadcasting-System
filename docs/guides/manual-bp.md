# 人工 BP、队长终端与导播接管

## 首次启动与更新

使用 Node.js 24，在 vite-project 执行 npm ci、npm run build、npm run server。默认只监听 127.0.0.1:3001。用 /control#token=local-control 打开开发环境导播。正式部署复制 .env.example 为 .env，设置互不相同且至少24字符的 CONTROL_TOKEN 和 OVERLAY_TOKEN，采用实际 HTTPS/WSS 入口，并在 ALLOWED_ORIGINS 明确列出页面来源。不可把开发口令用于公网。

Windows 可用 start-broadcast.bat；本地启动无需隧道时直接 npm run server。脚本会终止占用3001的进程及已有 cloudflared；已运行其他服务时先使用手动启动方式。公网隧道只是访问入口，队长链接仍需导播单独生成。

更新前停止服务，备份 data/lol、public/playerImg、public/teamLogo 及自有素材目录。新版自动将旧 screen/lcu 输入模式改为 manual。进行中的 BP 重启后暂停，确认记录后由导播恢复；不会补交队长离线点击。迁移不删除旧截图、用户图片和项目资料。

## 创建比赛与规则

导播填写两队、Logo、P1–P5选手、系列赛和本局规则。选手席位不要求五种分路齐全。teamId 与 playerId 跟随真实身份，屏幕左右位置与蓝红方分开。

保留 BO1/BO3/BO5/BO7、逐局规则覆盖、跨局限制。可用阶段序列配置每队0–5 Ban、Pick次序、每步1或2个英雄及可用英雄池；每队必须完成5 Pick。0 Ban仍记录阵容与历史。公开轮流BP；倒计时未启用。赛前由主办方确认海克斯大乱斗房间能否兑现约定，网页不会改变随机英雄或自动操作游戏。

开始后规则冻结；临时调整需暂停，检查已有槽位与跨局冲突，满足合法性后再恢复。双选必须选齐后一次确认，任一英雄非法则整步拒绝。

## 发队长链接与授权

在队长面板为两队各生成一个链接，通过既有沟通渠道发给对应队长。生成后默认没有写权限，确认身份后分别启用。链接跟随 matchId/teamId；换边、下一局仍由服务器检查当前步骤。不要给队长 CONTROL_TOKEN。

队长点击英雄仅本机预选，明确确认后等待服务器成功回执才成为正式结果。对方与OBS只收到正式选择。断线、暂停、等待对方、完成、未授权或接管时显示原因且不能提交。多标签并发、过期步骤和旧局请求由服务器拒绝。

导播可单队暂停、禁用、接管或轮换邀请。轮换后旧连接关闭，旧链接失效；新凭据只在本次生成响应中显示，不广播。禁用后需重新生成链接。导播更改BP、规则或归属会使队长授权世代失效，只有明确重新启用后队长才可继续。

## 纠错、回退与历史

手动BP是主工作区。暂停后选择当前或历史 gameId，在纠错面板按稳定 slotId 替换、补录或清空；已完成/归档也可修正。填写原因，服务器校验英雄ID、重复、禁用与跨局限制。不存在的英雄不能强制写入。

替换保持当前进度、比分、局ID、遥测和赛后数据。清空中间槽保留后续槽位并暂停，补齐后明确推进/恢复；“尚未填”“跳过Ban”“选中英雄”有不同状态。回退至指定步骤会明确清空该步及后续记录。原始Pick顺序与最终选手归属分开，交换归属不改变选人顺序。

历史更正只改目标局。影响后续跨局限制时列出冲突，保留后续局记录供导播处理；恢复需合法。比分、胜负与下一局始终由导播确认。采集读到GameEnd仅提示，不自动更新系列赛。

## OBS 与游戏数据

在OBS添加1920×1080浏览器源，地址 /overlay/draft#token=只读口令，背景透明。Ban槽随本局规则变化。/overlay/ghud 使用相同只读口令显示独立遥测；导播数据管理页可查看来源、更新时间、缺失及过期状态。OBS没有任何写入权限。

游戏机使用 scripts/game-bridge.mjs 主动上传；导播先创建本局采集会话，再核对首包名单确认绑定。结构化数据与正式BP英雄独立保存，不一致由导播核对。未支持经济/伤害/治疗字段不伪装为0。手动更正冻结字段，恢复自动后才接收后续样本。详见 game-data-bridge.md。

## 备份、恢复与回退

导播可导出服务端比赛备份，再通过专用恢复操作导入；服务器校验英雄与规则后以暂停状态恢复。普通客户端快照不能用来覆盖服务端。比赛内容恢复与Undo均不会回滚队长授权。恢复后应重新生成并发送队长链接。

完整磁盘备份还需包含遥测、队伍库和上传素材。授权文件不得从旧备份覆盖回去，否则可能恢复旧凭据；发生系统级回退时先撤销/删除所有旧邀请并重新生成。迁回旧版必须恢复升级前全套比赛备份，旧版不能理解新的分组规则、槽位、nullable Picks与队长权限。不要把新版存档直接交给旧版写入。

## 素材与验收

沿用仓库173张本地基础头像和现有Champion Studio；这是16.19.1素材快照，赛前核对实际客户端与英雄池并固定版本。队伍Logo、选手照片、heroDataOverrides、heroArtOverrides和额外图片保持原目录备份，站外终端必须使用服务端可访问的URL，不使用 file:// 或导播磁盘路径。远程原画失败回退正确英雄头像。

开发仅检查明确的LoL项目目录，未扫描全盘。该本地旧副本没有 data/lol，不能据此推断其他安装目录没有资料；其他安装的运行数据与素材目录须在迁移前明确指定。新开发副本未覆盖任何旧安装。

自动化与实机验收分开记录。正式使用前需在第二台设备/不同网络验证邀请、撤权、换边、图片、断线重连；在实际OBS验证透明源与快速改选；实际游戏/房间验证Live Client支持字段、名单绑定、结束提示和重连。未完成这些彩排不能把自动测试当作实机通过。
