# 游戏数据桥接与接口能力

本版使用游戏电脑上的 Node 桥接程序主动上传结构化数据。权威服务可在本机或云端；不需要把游戏本地端口暴露到公网。BP 与遥测分别持久化、分别校验版本，桥接没有 BP、队长授权、比分或下一局的写权限。

## 启动与绑定

1. 先启动服务并在导播端创建比赛。在「游戏数据」面板为当前 `matchId/gameId` 创建采集会话。
2. 在游戏电脑创建未提交到 Git 的 `bridge.env`，填入面板刚显示的值：

```dotenv
BRIDGE_SERVER_URL=https://your-broadcast.example
BRIDGE_MATCH_ID=面板提供的比赛ID
BRIDGE_GAME_ID=面板提供的本局ID
BRIDGE_SESSION_ID=面板提供的采集会话ID
BRIDGE_TOKEN=仅本采集会话的上传口令
```

3. 从 `vite-project` 目录运行 `node --env-file=bridge.env scripts/game-bridge.mjs`。开发时同机服务可使用 `http://127.0.0.1:3001`；外网必须 HTTPS。不要把导播口令、LCU token 填入桥接文件。
4. 游戏实际运行后，程序每秒读取固定的 `https://127.0.0.1:2999/liveclientdata/allgamedata`，上传首个有效房间预览。导播核对模式、双方 Riot ID 与实际英雄后，点击确认房间，才将样本发布到 GHUD。网页 BP 英雄仍由人工管理。
5. 下一局重新创建会话并更新配置、重启桥接。停止按钮/删除会话、服务器重启、不同局、房间阵容改变、桥接实例改变、游戏时间回退均会让旧会话失效或要求重新绑定。不得复用旧局的包。

首次绑定必须人工核对，因为 Live Client 的公开样本没有可靠的赛事 `gameId`。本版以本机实例、阵容指纹、模式/地图和单调游戏时间保护已确认绑定；相同十人的重赛或重新连接也应创建新会话。临时本机 API 失联后恢复会换实例，宁可让导播重新确认。网络失败不缓存或重放旧包；服务端还要求捕获时间与服务器相差不超过 30 秒，请同步两台电脑的系统时钟。

## 字段与含义

以下是适配器支持的字段，不代表已证明海克斯大乱斗所有客户端/观战方式都提供这些字段。正式比赛前必须实机核对。

| 数据 | 来源 | 处理 |
| --- | --- | --- |
| 游戏时间、模式、地图 | `gameData` | 按真实样本更新，不用本地时钟外推游戏时间 |
| Riot ID、队伍、英雄、等级 | `allPlayers` | 英雄名/资源标识映射到仓库已有 Riot 数字 ID；无法映射时保留原名和未知 ID |
| K/D/A、补刀 | `allPlayers[].scores` | `kills/deaths/assists/creepScore`；缺失为未知，真实 0 保持 0 |
| 事件、结束提示 | `events.Events` | 保留原始证据与事件 ID；`GameEnd` 只提示，不归档 BP、不改比分 |
| 总经济、伤害、承伤、治疗 | 此读取接口未提供可靠对应总量 | 显示不支持；允许导播录入并冻结，来源明确为人工 |
| 当前剩余金币 | `activePlayer.currentGold` 只针对当前玩家 | 不作为总经济，也不合成队伍经济 |
| 中立资源 | 本版不采集 | ARAM 明确不适用，其他模式为不支持，不显示虚构计数 |

未启动游戏时也可按本局十个稳定选手 ID 人工录入统计，初始指标全未知，连接显示等待；BP 的英雄不会被当作实际游戏英雄。绑定前填写名字、换人或重排会更新预期选手表，人工覆盖跟随稳定 ID，换下选手的旧覆盖仍保留并提示。确认采集房间后，身份映射保持锁定，BP 编辑不会改写实际样本；需要调整映射时先轮换采集会话，再重新核对房间。采集接通后，仅按同队的精确 Riot ID 将接口身份映射到赛事选手，不按数组顺序猜归属；未映射的人工覆盖保留并提示，需导播核对名字。

GHUD 根据实际样本中的稳定选手身份寻找当前真实队伍的名字、比分与 Logo，独立处理接口 ORDER/CHAOS 与网页蓝红方；无法映射时显示 ORDER/CHAOS 未匹配，避免换边后串队。全队击杀只在该接口队伍有五位不同选手且五个击杀值均已知时合计，残缺名单不显示虚假的队伍总分。

人工录入会覆盖显示并冻结相应字段，后续样本只更新底层原始值。导播点击恢复自动后，重新显示最新采集值；不支持的字段仍然不支持。五秒未收到正式样本即标记过期，保留最后可信值和更新时间；停止/重启为断开。缺失、不支持、过期与真实 0 独立表示。

数据存入与比赛目录同级的独立遥测文件，以稳定 `gameId` 隔离。JSON 导出包含最后可信原始样本、显示结果、人工覆盖和操作审计，不含上传口令或哈希。首版保留每局最后一份可信 `allgamedata`（其中包含截至该刻的完整事件列表），不保存每秒样本时间序列。它是本次采集到的赛后记录，不宣称具有完整的官方赛后伤害面板；若客户端结束前未提供某项数据，需人工补录。BP 归档仍需要导播确认，本局结束提示不会自动更新系列赛。

## LCU 只读连接

`LOL_LCU_ENABLED=1` 可开启服务机器本机的 League Client 状态检查。保留原有环境变量/lockfile/进程凭据发现以及仅本机 GET 请求，仅读取 gameflow 状态，不读取并提交禁选。服务在云端时无需启用。凭据、lockfile 和授权头都不发给网页；旧 `screen/lcu` BP 输入模式迁移为手动。

## 验证边界与实机步骤

自动化已覆盖真实接口结构样本的解析、未知/0 区别、总金币不误用、导播确认、局/会话隔离、乱序拒绝、房间变更撤销、冻结/恢复、结束仅提示、过期与重启撤销。样本测试不是游戏已接通的证明。

待实机验收：在比赛使用的实际客户端与海克斯大乱斗房间启动游戏，先访问本机 Swagger 检查字段，再运行桥接；核对十位选手和英雄、时间、K/D/A、等级、补刀和事件；拔网/恢复、切换房间、重赛并核对旧会话被拒绝；修改 BP 与人工统计并确认不会互相覆盖；结束后由导播确认胜负，导出本局 JSON，再从另一设备与 OBS 验证显示。观战方式不提供 Live Client 时，连接状态应保持等待/失联，不能显示假实时数据。

核查来源（2026-11-13 America/Los_Angeles）：[Riot 官方 Game Client / Live Client 文档](https://developer.riotgames.com/docs/lol#game-client-api)、[官方 allgamedata 样本](https://static.developer.riotgames.com/docs/lol/liveclientdata_sample.json)。LCU 为未受 Riot 官方支持的本地接口，不能保证版本稳定；本机 Swagger 为实际版本核对入口。没有使用截图、OCR 或推算统计。
